# CODEMAP — Create: Avionics

## 1. What this is

Create: Avionics (`ink.astrius.create_avionics`, v0.5.2) is a NeoForge 1.21.1 Minecraft mod that supplies ComputerCraft (CC: Tweaked) peripherals for the Create mod and its physics-flight ecosystem — Create: Simulated, Create: Aeronautics, and Create: Offroad. It contains no blocks or assets of its own: every feature is a mixin into an upstream block entity plus a peripheral class exposing a `@LuaFunction` surface, with a shared kinetic "SCADA" readback layer (`KineticScadaSurface` / `KineticReadback`) spanning both the Create and Simulated peripheral hierarchies. The same annotated Java sources also drive the documentation site: a patched cct-javadoc doclet emits Lua stubs that illuaminate compiles into the GitHub Pages site.

## 4. Module & package guide

### Build modules

- **`common/`** — all real code. Compiles against vanilla + NeoForm deobf (not full NeoForge); upstream mods are `compileOnly`. Exposes its source dirs as `commonJava`/`commonResources` consumable configurations.
- **`neoforge/`** — loader shim. `multiloader-loader.gradle` injects common's `.java` sources directly into `compileJava` (unified compilation, no jar dependency), merges resources, and adds the neoforge-variant upstream deps. Single class: `CreateAvionicsNeoForge` listens to `RegisterCapabilitiesEvent` (guarded on `Mods.COMPUTERCRAFT.isLoaded()`), registers `PeripheralComposition` for `SEQUENCED_GEARSHIFT`, and registers `PeripheralCapability` for six Create BE types (mechanical bearing/piston, gantry shaft, rope/elevator pulley, elevator contact) via the `api/create` Ext accessors.
- **`buildSrc/`** — the two precompiled convention plugins above. Archive naming: `create_avionics-{common|neoforge}-1.21.1-0.5.2.jar`.

### Packages (`common/src/main/java/ink/astrius/create_avionics/`)

- **`CreateAvionics`** — minimal entry point (`MOD_ID`, `LOGGER`); registration lives in compat integration classes.
- **`compat/cc`** — composition plumbing. `ComposingPeripheral` (an `IDynamicPeripheral` grafting CC generic-source methods onto a primary peripheral; primary wins name collisions) and `PeripheralComposition` (opt-in `Set<BlockEntityType<?>>` read by `PeripheralAccessMixin`).
- **`compat/create`** — `KineticPeripheral` (extends Create's `SyncedPeripheral`, implements `KineticScadaSurface`), `KineticScadaSurface` (default `@LuaFunction` methods: `getSelfId`, `getSourceId`, `getSubnetworkAnchorId`, `getNetworkId`, `getKind`, `getSpeed`, `hasSource`, `isOverstressed`, `getStressImpact`, `getStressContribution`), `KineticReadback` (static SCADA logic: network walking up to 256 hops, kind classification `generator/split_shaft/consumer/passthrough`). `CreatePeripheralRegistry` is the ordered `(block entity class -> peripheral factory)` table -- matched by `isInstance`, so more specific entries must come first (`ElevatorPulleyBlockEntity` ahead of `PulleyBlockEntity`); `ComputerBehaviourMixin` only consults it while intercepting `ComputerBehaviour.getPeripheralFor`.
- **`compat/simulated`** — `SimPeripheral`/`SimKineticPeripheral` base classes; `SimulatedCompat` (cached `MethodHandle`s bridging members whose spelling differs across supported Simulated versions, e.g. `getLaserRange` -> `getRaycastLength` in 1.3.0); `SimulatedCCIntegration` (SPI `SimModCompatibilityService`, mod id `"computercraft"`) registers `KineticSource` as a CC `GenericSource`, all Simulated peripherals via `SimPeripheralService`, `PORTABLE_ENGINE` with `PeripheralComposition`, and `DOCKING_CONNECTOR` as a wired network element. `peripherals/generic/KineticSource` (`@cc.module kinetic_provider`) is the fallback for any `KineticBlockEntity` without a dedicated peripheral.
- **`compat/aeronautics`** — `AeroCCIntegration` (SPI, guarded on `isLoaded("aeronautics")`) + propeller/gas peripherals.
- **`compat/offroad`** — `OffroadCCIntegration` (SPI, guarded on `isLoaded("offroad")`) + `WheelMountPeripheral`.
- **`api/`** — mixin-implemented accessor interfaces: `api/simulated` (AltitudeSensorExt, AnalogTransmissionExt, GimbalSensorExt, LinkedTypewriterExt, NavigationTargetExt, SwivelBearingExt), `api/aero` (GasProviderData, GyroscopicPropellerBearingExt), `api/create` (ElevatorContactExt, ElevatorPulleyExt, GantryShaftExt, LinearActuatorExt, MechanicalBearingExt, SequencedGearshiftExt), `api/offroad` (WheelMountExt — steering/brake overrides plus telemetry).
- **`mixin/`** — 25 mixins, all shared-side, `compatibilityLevel JAVA_21`. Key takeover points: `simulated/ComputerCraftPeripheralsMixin` cancels upstream Simulated's CC `init()` entirely (logging that it did, at INFO); `create/ComputerBehaviourMixin` delegates to `CreatePeripheralRegistry` for 11 Create BE types; `cc/PeripheralAccessMixin` (+ two accessors) layers generic-source methods onto capability-supplied peripherals; the rest add fields/overrides (vertical speed, analog signal override, gimbal physics via Sable, typewriter key events, nav-target metadata, gyro manual target, gas-amount control, wheel steering/brake overrides) persisted to NBT where stateful.

## 6. Lifecycle

```
commit → push/PR to main
  └─ ci.yml: JDK 21 → wrapper validation → ./gradlew build → upload jars artifact (14d)
  └─ docs.yml (main push): ./gradlew :common:luaJavadoc → illuaminate 0.1.0-83-g1131f68
       doc-gen (illuaminate.sexp) → build/illuaminate/ → deploy to GitHub Pages

tag vX.Y.Z (subject = one-line release summary) → push
  └─ release.yml:
       1. verify tag (minus "v") == gradle.properties mod_version, else fail
       2. ./gradlew build; collect neoforge jars (excluding -sources/-dev/-dev-shadow)
       3. GitHub release "Create: Avionics {version}" via softprops/action-gh-release@v3,
          generated notes, prerelease if version contains "-", jars attached
       4. changelog: awk-extract "## [{version}]" section from CHANGELOG.md;
          fallback to the git tag subject if absent
       5. Modrinth publish (Kir-Antipov/mc-publish@v3.3, project h4nsLvjf, alpha,
          neoforge, 1.21.1, create_avionics-neoforge-*-{version}.jar)
       6. stable releases only: regenerate updates.json from all stable v* tags
          (values = tag subjects), commit "chore: update updates.json for {tag}" to main
          → consumed by NeoForge update checker via updateJSONURL in neoforge.mods.toml
  └─ docs.yml deploy job also runs on v* tags
```

Conventions: `CHANGELOG.md` follows Keep a Changelog 1.1.0 + SemVer (`## [Unreleased]`, then `## [x.y.z] - YYYY-MM-DD` with `### Added/Changed/Fixed/Removed/Docs`); tag subjects are one-line summaries that become `updates.json` version descriptions and the Modrinth changelog fallback. Dependabot covers GitHub Actions only (weekly, `ci` commit prefix). Released versions: 0.2.0 → 0.5.2 (2026-07-25; 0.5.0 yanked); `1.21.1-recommended`/`-latest` both point at the newest stable.
